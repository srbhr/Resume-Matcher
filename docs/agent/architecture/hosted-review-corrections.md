## Evidence and important distinctions

Behavioral fixes were driven by failing cases at actual API, transaction, hook, component or browser boundaries. Independent integration review found and corrected additional cases: approved append changes disappearing at confirmation, invented appended revenue, an abandoned viewer retry reloading a different page, required direct-improve relations written separately, swallowed deadline errors, confirmation rejecting a valid near-limit preview, unbounded cleanup waiting and a zero-ID wizard echo overwriting the first of two identically identified entries.

The second hosted round also produced verified corrections at the original owning stages: configuration acknowledges an already committed file replacement despite a directory-sync error; attachment saves read the current queued revision and preserve newer edits; a retry restarts capped dashboard polling; optional null wizard hints normalize conservatively; and PDF cleanup cancellation retires the browser without losing capacity ownership. Ordinary cleanup errors after successful PDF production preserve the bytes.

Completion receipts now remain recoverable until the matching builder loads and validates the persisted resume, or deletion succeeds. Scheduling navigation alone is insufficient. Identity checks protect unrelated receipts, newer drafts, failed loads and unmounted builders. Real builder-to-wizard component controls verify recovery and acknowledgement.

JSON recovery distinguishes unmatched prose brackets from true array prefixes. Valid object responses following prose are accepted; complete, truncated or deeply nested array prefixes trigger corrective retry. The prefix scan is linear and excessive decoder nesting is contained rather than escaping as an unhandled parser error. Unterminated array strings containing complete object fragments are also rejected; the corrective retry must produce the actual result. Production keyword retention and the independent evaluation scorer recognize Latin technology terms adjacent to CJK text (such as `Pythonによる開発` and `熟悉Java开发`), while `Java` still does not match `JavaScript`. The final boundary correction covers supplementary Han, Hangul syllables/Jamo and Kana variants in both production and the independent scorer. Six pipeline/scorer regressions failed before the correction; 79 focused cases and 44 independent script-boundary controls pass.

Every document and API-key write uses consistent SQLite busy/locked translation. The two enrichment apply handlers now propagate `DatabaseBusyError` to the shared 503/Retry-After response; real writer-lock controls prove unchanged data and successful retry after lock release. The enrichment preview endpoint performs no write. Manual job/card creation is atomic. Processing retirement retries contention with bounded caller waiting; token checks protect newer attempts. A fresh upload whose initial claim fails can retire only its still-unclaimed processing row. Real SQLite writer, cancellation and injected-failure tests verify these cases.

Direct improvement now writes its resume and required Improvement relation in one transaction. Cancellation before commit leaves neither; expiration after commit can return a timeout with both records present. Tracker creation remains best effort. Confirmation has its separate durable replay contract. See [storage transactions](storage-transactions.md) and [preview confirmation](../features/preview-confirmation.md).

Cleanup waiting is bounded while tracked tasks retain ownership of work that cannot finish immediately. Processing retirement makes at most three write attempts with exponential backoff. Sustained contention logs exhaustion and leaves the same row available for explicit retry after lock release. Shutdown gives cleanup a grace period, then cancels and reaps it before disposing SQLite; reaping can wait for an in-flight operation to unwind. This is not a promise that cancellation instantly stops a converter, browser or database operation. See [AI operation budgets](ai-operation-budgets.md) and [PDF lifecycle](../design/pdf-template-guide.md).

Not-actionable comments have concrete explanations in the ledger, including the installed LZW iterator API, Python cancellation inheritance/reinjection behavior, valid TypeScript type queries, Next App Router navigation semantics, model-specific sampling defaults and already-supported full month names. Unsupported premises were not implemented as behavior changes. The final processing review was checked against real SQLite and installed Uvicorn: directly awaited claims receive wrapper cancellation and finish unwinding before the wrapper returns; four SQLite busy waits settle concurrently; Uvicorn drains or cancels requests before lifespan teardown registers its cleanup snapshot. Cubic's earlier chronology claim was disproved by Git ancestry. CodeQL alert 10 was dismissed only after tracing the sole production exception constructor to a fixed public limit and verifying the real API response contains no private input.

The delayed review batch added final integration corrections in #992. Oversized individual enrichment prompts now produce per-item errors while preserving successful enhancements; an entirely failed attempt still errors and the shared operation deadline still returns 504. Upload 422/503/504 responses retain the committed resume ID and master designation, allowing recovery of the same row without asserting a possibly stale processing status. Post-apply enrichment refresh blocks modal close until it settles, preserving its success or retry state.

Content-preservation checks now distinguish date context from bare counts in the 1900–2100 range, penalize substantial subset expansions/truncations, warn about weakly grounded appended rows, and match duplicate identity buckets consistently during confirmation. Complete idless wizard echoes also consume existing duplicate signatures once. These remain lexical safeguards and explicit user review boundaries, not a proof of semantic entailment. The reported finalized-metric inconsistency was already corrected in the assembled stack.

The final PDF controls reproduced a failed page close forcing another active export to replay. Retirement now detaches the generation immediately but drains existing render scopes before closing it once. A real stopped Playwright driver can leave a stale browser-connected flag after a browser-close error; successful first driver shutdown now acknowledges teardown. Failed one-shot driver shutdown is quarantined with its objects and capacity until application restart, because a repeated stop can silently do nothing. Shutdown reports quarantined resources and gives active owners a bounded drain window. Real Chromium controls cover these distinctions, simultaneous cleanup failures and both shutdown timing paths. Cancellation before the retirement task starts or while it drains also preserves explicit quarantine ownership. Event-driven test synchronization replaces fixed sleeps; nested test cleanup restores bookkeeping even when teardown raises, without treating this as production teardown proof.
